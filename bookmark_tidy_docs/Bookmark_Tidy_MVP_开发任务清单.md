## v0.2+ Backlog

以下为原 6 周计划，保留用于 v0.1 后的工程拆分与排期。

## 1. Backlog 使用方式

- 每个任务应对应一个 Issue 和一个可独立评审的 Pull Request。
- 任务进入开发前必须满足“Ready”；合并前必须满足“Done”。
- `P0` 是发布阻塞项，`P1` 是 MVP 必需项，`P2` 可在时间不足时延后。
- 工作量使用 Story Point：`1` 约半天，`2` 约 1 天，`3` 约 1–2 天，`5` 约 2–3 天，`8` 需要继续拆分。
- 标记为 `[关键路径]` 的任务延期会直接影响 MVP 发布。

### Definition of Ready

- 目标、输入、输出和不做什么已经明确。
- 依赖任务已完成，或有可用 mock/stub。
- 验收标准可测试，没有“优化一下”“体验更好”等模糊表述。
- 涉及书签写入时，已说明快照、失败和撤销行为。

### Definition of Done

- 实现、类型检查、Lint 和相关测试通过。
- 没有绕过 Bookmarks Adapter 或 Operation Engine 直接写书签。
- 错误状态、空状态和加载状态完整。
- 新增数据结构有版本或迁移考虑。
- PR 包含验证步骤；高风险任务包含恢复验证。

## 4. E0 — 工程基础与 Chrome 集成

### BT-001 建立扩展工程骨架 `[P0] [关键路径]` — 3 SP

**实现范围：**

**验收标准：**

**依赖：** BT-001

**实现范围：** 创建 `background`、`pages`、`bookmark`、`rules`、`storage`、`types` 和 `utils` 模块；禁止 UI 直接依赖 Chrome 原生 API。

**验收标准：**

- 目录职责写入 README。
- Chrome API 只能通过 adapter 层访问。
- 分析模块不导入执行模块。

### BT-003 建立页面与 Service Worker 消息协议 `[P0] [关键路径]` — 3 SP

**依赖：** BT-001

**实现范围：** 定义带版本和类型的 request/response/event 消息；覆盖扫描请求、进度、结果和错误。

**验收标准：**

- Manager 能请求测试数据并收到结构化响应。
- 未知消息类型返回明确错误。
- 请求超时和 Worker 不可用有处理路径。

### BT-004 实现 Bookmarks Adapter 基础接口 `[P0] [关键路径]` — 3 SP

**依赖：** BT-002

**实现范围：** 封装 `getTree`、`create`、`move`、`update`、`remove`；统一 Promise、错误和日志格式。

**验收标准：**

- 测试目录中可完成读取、创建、移动、更新和删除。
- 上层代码不直接调用 `chrome.bookmarks`。
- Chrome API 错误转换为领域错误类型。

### BT-005 实现 Storage Adapter 与 schema 版本 `[P0]` — 2 SP

**依赖：** BT-002

**实现范围：** 封装设置、历史和快照存储；加入 `schemaVersion` 和迁移入口。

**验收标准：**

- 可以读写版本化测试对象。
- 数据损坏时返回可恢复错误，不导致页面白屏。
- 清除历史不会误删用户设置。

### BT-006 建立日志和错误边界 `[P1]` — 1 SP

**依赖：** BT-001

**实现范围：** 统一日志级别、错误代码和 UI 错误边界；生产日志不得包含完整书签库。

**验收标准：**

- 未捕获页面错误显示恢复入口。
- 日志可关闭，默认不记录完整 URL 集合。

## 5. E1 — 书签扫描与领域模型

### BT-101 定义标准化书签节点模型 `[P0] [关键路径]` — 3 SP

**依赖：** BT-002

**实现范围：** 定义 `BookmarkNode`、`BookmarkFolder`、`BookmarkItem`、`BookmarkPath` 和扫描结果类型。

**验收标准：**

- 模型覆盖 ID、类型、标题、URL、父级、索引、路径和日期。
- 文件夹与书签使用可区分联合类型。
- 不允许书签节点缺少 URL。

### BT-102 实现 Bookmark Scanner `[P0] [关键路径]` — 5 SP

**依赖：** BT-004、BT-101

**实现范围：** 读取 Chrome 书签树并转换为标准化模型；保存根节点和受保护目录信息。

**验收标准：**

- 嵌套目录、空目录和特殊字符标题均可处理。
- 扫描过程不调用任何写 API。
- 同一输入产生稳定节点顺序。

### BT-103 建立书签索引 `[P0]` — 3 SP

**依赖：** BT-102

**实现范围：** 建立 `byId`、`byParentId`、`byDomain`、`byNormalizedUrl` 和路径索引。

**验收标准：**

- 索引与节点总数一致。
- 删除测试节点后重建索引无陈旧引用。
- 5,000 条数据下查询无明显延迟。

### BT-104 实现扫描进度和取消 `[P1]` — 2 SP

**依赖：** BT-003、BT-102

**实现范围：** 向 Manager 推送扫描阶段、处理数量和完成状态；支持取消长任务。

**验收标准：**

- UI 可显示“读取、标准化、建立索引”阶段。
- 取消后不保存半成品为有效扫描结果。

### BT-105 实现搜索服务 `[P1]` — 2 SP

**依赖：** BT-103

**实现范围：** 支持标题、URL、域名和路径搜索，以及类型筛选。

**验收标准：**

- 搜索不区分英文大小写。
- 结果携带完整路径，可在书签树中定位。

### BT-106 建立扫描器测试夹具 `[P0]` — 1 SP

**依赖：** BT-101

**实现范围：** 准备 Small、Medium、深层目录、多语言和异常节点夹具。

**验收标准：**

- 测试夹具不含真实用户隐私数据。
- 能复现空目录、重复标题和特殊 URL 场景。

## 6. E2 — 确定性清理引擎

### BT-201 定义 URL 归一化策略 `[P0]` — 2 SP

**依赖：** BT-101

**实现范围：** 明确协议、主机名、默认端口、末尾斜杠、参数排序和跟踪参数规则。

**验收标准：**

- 策略文档列出“移除”和“不得移除”的参数类型。
- 原始 URL 始终保留。

### BT-202 实现 URL Normalizer `[P0] [关键路径]` — 5 SP

**依赖：** BT-201

**验收标准：**

- 正确处理大小写、默认端口、末尾斜杠和 `utm_*`/`fbclid`。
- 不错误合并不同域名、路径或关键查询参数。
- 非法 URL 返回结构化失败结果，不抛出未处理异常。

### BT-203 建立 URL 归一化回归测试集 `[P0]` — 3 SP

**依赖：** BT-201

**实现范围：** 覆盖 GitHub、文档站、电商、搜索、登录和带锚点 URL。

**验收标准：** 至少包含正常、等价、不可合并和非法输入四类样例。

### BT-204 实现精确重复检测 `[P0]` — 2 SP

**依赖：** BT-103

**验收标准：** 相同原始 URL 正确分组；单条记录不输出建议。

### BT-205 实现标准化重复检测 `[P0] [关键路径]` — 3 SP

**依赖：** BT-202、BT-103

**验收标准：**

- 以 `normalizedUrl` 分组。
- 建议保留项可解释，并显示所有原始 URL 和路径。
- 疑似但不确定的内容不默认选择删除。

### BT-206 实现空文件夹检测 `[P0]` — 3 SP

**依赖：** BT-102

**验收标准：**

- 不返回根节点、受保护目录或含子节点的目录。
- 支持识别删除其他空目录后变为空的父目录，但分批展示依赖。

### BT-207 实现 Cleaner 聚合服务 `[P1]` — 3 SP

**依赖：** BT-204、BT-205、BT-206

**实现范围：** 统一运行清理规则，输出问题计数、建议和分析耗时。

**验收标准：** 可单独启停每类检查；规则失败不阻断其他检查。

## 8. E4 — 执行、历史、快照与撤销

**依赖：** BT-305、BT-401

**验收标准：**

**依赖：** BT-402、BT-004

**验收标准：** 外部修改导致不一致时标记冲突，不继续执行高风险操作。

**依赖：** BT-403

### BT-405 实现部分失败与重试 `[P0]` — 3 SP

**依赖：** BT-404

**验收标准：** 独立操作可继续；依赖失败的操作自动跳过；只重试安全且幂等的操作。

### BT-406 实现历史与快照存储 `[P0] [关键路径]` — 3 SP

### BT-407 实现 Undo Engine `[P0] [关键路径]` — 5 SP

**依赖：** BT-406

**验收标准：**

### BT-408 实现撤销冲突和安全降级 `[P0]` — 2 SP

**依赖：** BT-407
